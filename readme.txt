    我大致是在 2021年4月份开始有了编写一个基于 http 协议的文件服务器的想法。
    我当时敢于做这个东西的主要理由是，我在2月左右学习了一些 asio 的使用技巧，所以编写网络程序是个合理的练手项目，其次我当时关注的一个b站up主使用go语言编写了一个基于http的文件服务器，可以同步自己手机的图片数据到http服务器里，我当时十分想要这样一个东西。最后，彼时的我已经学了c++一年，编写这样一个程序对于增强我对于c++的信心大有帮助。
    于是我开始写了，并在21年的5月完成了一个粗糙的版本。那个版本目前还可以在 old 中找到，名字就叫 asio-sync-http-server.cpp。这个程序基于 asio，使用阻塞式io，并且配合上了c++的std::async，除此之外，它是基于windows的。完成那个服务器端的主要挑战是，当时的我对于windows的编码问题理解的一塌糊涂，导致我的服务端一做出来就在浏览器上乱码，其次asio的异步函数我完全无法理解，所以我被迫简化了问题，只使用了同步阻塞模型。但无论如何，最终这个项目仍然跑起来了，尽管它只支持最简单的文件列表。
    2024年我开始重新实现旧项目，其中一个目标就是拓展当时2021年没能完成的http服务器，并且我期望除了文件列表的功能外，能够支持文件上传功能，另外，我希望这就是一个独立于linux平台的web服务器，且它应该是不依赖第三方库的。最终我做到了，并且我还给出了多进程和多线程2个版本。
    2026年我对于这个项目仍然有一些不满意的地方，并且多线程版本和多进程版本总是莫名其妙的crash，另外站在现在的角度上来看的话，将所有逻辑和http服务器绑死在一起不是一个好主意，因此我开始考虑将http服务器独立出来，然后把所有的处理逻辑全部交给用户回调函数去做。最终我做出了V2，它基于完全重做的线程池，有异步日志功能，基于状态机实现的完整的http请求解析等功能。从这个版本开始，我真正意义上有了 Multipart 的能力。之后的用户态函数基于这个服务器就变得容易多了，这也是我目前直接可用的版本。
